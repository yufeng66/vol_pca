## Project Setup

Cheap-VaR research on SPX implied volatility surfaces: greeks-based VaR vs full revaluation, with PCA as the current (not only) model of surface dynamics. Python project managed with `uv` (Python 3.14, pinned in `.python-version`); the setup mirrors the `~/vix_refactor` project minus its PyTorch/trading dependencies.

Commands:
- `uv sync` — create/update `.venv` from `pyproject.toml`. Default groups: `dev` (pytest) and `gpu` (torch 2.12.0 pinned, resolved as +cu130 from the PyTorch index on Linux/Windows — the exact build `~/vix_refactor` verified on this machine). `uv sync --no-default-groups --group dev` gives a torch-free env; everything except `vol_pca/rainbow_torch.py` (and its tests, which importorskip) runs without torch.
- `uv run python <script>` — run a script inside the venv.
- `uv run pytest` — run tests (configured for `tests/`, with repo root on `pythonpath` so in-tree packages import without installing).
- `uv run pytest tests/test_foo.py::test_bar` — run a single test.
- `uv run jupyter notebook` — notebooks.
- `uv add <pkg>` — add a dependency.

Main deps: pandas, scikit-learn, scipy, matplotlib, notebook; torch (gpu group, default-installed) used only by `rainbow_torch.py`.

Run the full pipeline: `uv run python scripts/run_analysis.py` (~10s; writes `data/daily_results.csv`, `data/attribution_daily.csv` and `data/factor_model.npz`, all gitignored). Rainbow-book attribution: `uv run python scripts/run_rainbow_attribution.py` (~6.5 min on the GPU; writes gitignored `data/rainbow_attribution.csv`, consumed by `rainbow_attribution.ipynb`).

## Project Goal & Status

**The goal is cheap VaR, not PCA** (user, 2026-08-03): find ways to compute VaR via a greeks-based approach — a handful of (bumped) revaluations projected across thousands of scenarios — instead of fully revaluing every scenario, because the real book's exotics are simulation-priced and every valuation is costly. Capturing vol-surface dynamics compactly is the enabling sub-problem; PCA factors are the representation tried so far, **not the only one that will be tried** — candidate alternatives should be benchmarked on the same test book, scenario engine, and rolling backtest. First alternative tested (2026-08-03): fixed key-rate level/skew shapes per quarterly knot (`key_rate.py` + `key_rate.ipynb`) — interpretable, fit-free, 16 revals, but rolling hedged VaR |gap| 7.4% mean vs 5.6% for PCA k=4+cube and the same −67% crisis tail; details in the `key_rate.py` bullet below. Test vehicle: every day sell a $1M-notional 1Y SPX call spread (short 100%, long 110% strike), giving a steady-state book of ~250 spreads; attribute daily P&L, compute the book's exposure to each factor of surface moves, and estimate vol P&L as exposure × daily factor movement (done). The headline framework is **sticky-strike** (user decision 2026-08-01): factors fit to sticky-strike pillar changes, targeting the book's fixed-strike vol P&L ex term-roll carry (attribution `vol − vol_roll`; total +$15.5M, daily std $70k), paired with the plain BS delta. Presentation rule from the user: do **not** quote the total of `vol_surface`/`pl_vega_full` as a headline number — it and the smile slide are large offsetting coordinate artifacts of the moneyness split; quote the fixed-strike vol P&L instead. The central deliverable — greeks-projection VaR benchmarked against full revaluation — is in place (`var.py` + `historical_var.ipynb`): 1-day historical VaR of the last-date book over 3,138 joint scenarios — delta-hedged VaR99 $183k by full reval vs $185k (+0.9%) for the greeks projection at k=10 (~15 valuations per position vs 3,138; k=3 understates the tail by 10%, all-factor matches to 0.1%). A rolling backtest over all 2,889 as-of books tempers the single-date read: median hedged |gap| 3.0% at k=10 (4.3–5.9% at k=3–5), the third-order equity term is worth including (~0.5pp mean hedged improvement at small k for two extra spot bumps — a whole-history reversal of the misleading single-date test), and crisis-peak as-of dates understate by ~60% at any k — diagnosed as factor truncation from the frozen average-book weights, not vega convexity: the displaced book's vega sits in far-wing pillars the fixed weights ignore. The statics-only adaptive weighting built for that (`strike_histogram_weights`, user-requested, no greeks) caps the failure (worst understatement −61% → −22%, zero books beyond −30%) but is worse on average (hedged mean |gap| 6.6% vs 4.7% at k=10+cube, better on only 35% of days) — kept as a parallel drift alarm, not the headline method. **New thread (2026-08-05)**: the dataset was replaced by three co-quoted surfaces (SPX/SX5E/HSI, 2018-12-27→2026-07-31, 1,969 joint dates) to study the real book's exotics directly — first deliverable is a single 1Y rainbow call spread valued by implied-marginal + Gaussian-copula Monte Carlo (`rainbow.py` + `rainbow_option.ipynb`, details in the module bullet); the daily-sold rainbow book and its full-history P&L attribution are done (2026-08-05: `rainbow_attribution` driver + `rainbow_attribution.ipynb`, 6.5 min on device, residual 0.6% of P&L std — details in the `rainbow_torch.py` bullet); next is the cheap-VaR question on that book with nested revaluation as the expensive baseline — the batched GPU engines for it are in place (`rainbow_torch.py`, user go-aheads 2026-08-05): quadrature ~74× the numpy loop (4.5 ms/price at 48×48), CRN Sobol 17–22µs/price, device-resident marginal factory ~50× the CPU table build, one autograd backward for every vintage's exact spot deltas.

## Architecture (`vol_pca/` package)

The load-bearing design choice: all pricing looks vols up on a fixed per-date **pillar grid** (8 TTM pillars × the 13 quoted moneyness columns, `surface.py`) with **bicubic-spline** interpolation (cubic per axis, not-a-knot ends; `grid_lookup(..., interp="linear")` keeps the old bilinear lookup). Spline interpolation with fixed knots is still *linear in the pillar values*, so every queried vol is an exact linear combination of pillar vols — the weights are dense cardinal-basis products (global, can be negative) instead of bilinear's 4 local ones — and scattering each option's vega onto the pillars via those weights keeps the exact identity `pl_vega_lin == bucket_vega · Δσ` (asserted in tests to 1e-9). Caveat of the dense weights: bucketed vega gets oscillatory side-lobes (gross |bucket vega| ≈ +34% vs bilinear at unchanged net), so it is a factor-model input, not a per-pillar hedging report. The identity holds for sticky-moneyness Δσ (pillar-point differences); the headline sticky-strike Δσ samples between pillars, so its all-factor estimate carries a small extra reconstruction error on top of vega convexity (all-factor R² 0.985 vs the target).

- `data.py` — loads/cleans the CSV (EOD filter, dup drop, corrupted-upper-wing repair) into `SurfaceData`: per-date pillar grids plus log-linear discount/forward curves.
- `pricing.py` — Black-76 on the forward; spot greeks assume fixed F/S. Returns (price, delta, gamma, vega, vanna) with `greeks=True`.
- `book.py` — daily simulation and sequential attribution against the previous close. Delta is the **smile delta** (surface is moneyness-quoted, so a fixed strike slides along the smile as spot moves) — this sequential view stays sticky-moneyness; the headline factor framework instead pairs sticky-strike factors with the plain BS delta. Vanna is explicit because SPX spot-vol anticorrelation makes it a large systematic drag (−$32M over the sample).
- `attribution.py` — independent (non-waterfall) Black-Scholes-input attribution: each component is a single-input revaluation from the same previous-close base (equity split delta/gamma/higher, the option's own implied-vol change, zero rate r, implied dividend yield q, time, exact vanna cross). The time component is split by the BS PDE into `time_funding` (financing premium + carrying the delta hedge) vs pure gamma theta, so a delta-hedged view = `pl − eq_delta − time_funding`. The vol component splits exactly (telescoping full revals) into `vol_surface` (≡ book.py's `pl_vega_full`) + `vol_roll` (term roll; `vol_carry_ex` is its ex-ante version off the previous close — anticipatable carry, corr 0.98) + `vol_slide` (spot-driven smile slide). The headline PCA target is `vol − vol_roll` (fixed-strike vol ex anticipatable carry) = `vol_surface + vol_slide`. Daily totals match `simulate_book` exactly (tested); residual std is ~0.8% of P&L std. Inspected in `attribution.ipynb` (root; executed outputs committed); the factor model and this reconciliation are illustrated in `pca_factors.ipynb`. Note the q backed out of forward-vs-spot spikes on some stress dates (e.g. 2018-02-06) — a data snap inconsistency the `div` component absorbs and flags.
- `factors.py` — PCA on daily pillar Δσ with a per-pillar weight transform (`fit_pca(weights=...)`): `"cov"` (plain), `"corr"` (standardized), or a custom array. The **headline model** is vega-weighted (`w_p` = book's average |bucket vega|) PCA on **sticky-strike** pillar changes from `sticky_strike_dsigma(sd)` (new surface sampled at m·S₀/S₁ with the pricing interpolant, `interp="cubic"` default with `"linear"`/`"pchip"` variants: surface move + smile slide at fixed TTM, roll excluded; the 50/150 edge columns clamp). Target: fixed-strike vol P&L ex roll. k=3 R² by weighting: vega 0.811, corr 0.646, cov 0.474 (vega k=10: 0.934; all-factor ceiling 0.985). Exposures `E_k = (bucket_vega/w)·L_k`, scores `f_k = L_k·((Δσ−μ)∘w)`, estimate `= bucket_vega·μ + Σ E_k f_k`. Sticky-strike factors are far less spot-entangled than sticky-moneyness ones (PC1 |corr| with spot returns 0.34 vs 0.86) and pair with the plain BS delta. `include_roll=True` folds the term roll in too (pillar tracks a fixed option: strike and expiry, day-t lookup at τ−dt), making the basis complete against the full attribution `vol` (all-factor corr 0.994, cumulative within $0.5M with no carry line; loadings identical to ex-roll — roll just moves into the factor mean, ≈ −$5.3k/day; shortest pillar clamps at the 0.08 TTM edge); explored in `roll_in_pca.ipynb`, which also shows k=3 suffices for exposure reporting (R² 0.82) but stress days need k≈10 (big-move R² 0.66 → 0.83, p99 error $115k → $57k). The comparison that motivated the switch is `sticky_strike.ipynb`: with cubic sampling sticky-strike beats moneyness-PCA + slide at every k (k=3 R² 0.81 vs 0.77, ceiling 0.985 vs 0.955 — linearizing the net $70k move beats linearizing the two big offsetting pieces); under the old bilinear sampling the ranking was reversed — kinked bracket-crossing samples read as pillar noise and faked a ~+$9k/day carry drift in the factor mean (linear interpolation overestimates the convex smile between nodes). The factor machinery is illustrated in `pca_factors.ipynb`. `fit_pca` stores each factor's fit-sample score std (`model.score_std`) — the natural 1σ bump sizes for the bump path. `bumped_factor_exposures(price_fn, model, k, eps)` computes the same exposures by bump-and-revalue — central differences of the book value along each factor's unit-score surface move `L_k/w` (2k+1 revaluations), plus the PC1 curvature `d²V/df₁²` free from the same pair — for pricers with no cheap vega (the real book's simulation-priced rainbows); `book_price_fn(book)` in var.py is the test-book closure, and the bump route matches the analytic exposures over the whole rolling history (worst date 6e-6 relative). The `½c·f₁²` quadratic add-on (bumps sized ~3σ of fit scores; curvature is ε-stable, c(±1σ)≈c(±3σ)) improves the daily vol estimate (k=10 R² 0.937→0.946, big-move RMSE −9%) and trims VaR nonlinearity modestly (hedged mean |gap| 4.74→4.65%, days>10% 11.4→9.8%, k=4 5.64→5.39) but does not touch crisis-book understatements — that residual is spot×vol cross + truncation, owned by the gate/screen below.
- `var.py` — historical 1-day VaR, two engines over the same scenario set. Each historical day pair is one joint scenario (spot ratio, fixed-moneyness pillar Δgrid, Δr/Δq at each leg's TTM, calendar-gap dt) applied to a fixed as-of book (`build_book`: close-of-day legs incl. that day's new spread). `full_reval_pnl` samples the shocked grid at each leg's new moneyness and dt-decayed lookup TTM with the BS time input frozen — slide and roll-down realize on the as-of surface (the roll-in basis as a scenario engine); scenario P&L is pure market shock (attribution's equity+vol+rate+div+vanna, no theta/funding). `greeks_pnl` projects scenarios from one base-date greeks pass (delta/gamma, bucketed vega → factor exposures, bucketed vanna paired with the k-factor Δσ reconstruction, 1bp rho/div bumps); factor scores come from `scenario_dsigma` — each scenario's pillar move re-anchored on the as-of surface, grid lookups only. Reusing the fitting sample's historical scores instead drops R² 0.95→0.81 and understates hedged VaR99 by 12%, so don't. - `key_rate.py` — **the first alternative surface representation** (user-specified 2026-08-03): desk-style key-rate sensitivities instead of fitted factors, no fitting anywhere. Two shapes per quarterly knot (3/6/9/12M, tent weights in TTM so the four level sens sum exactly to net vega; TTM < 3M clamps onto the 3M knot): **level** = parallel bump at the spread's own maturity, **skew** = tilt (m−100)/5 vol pts (+1 @ 105, −1 @ 95, deliberately unclamped into the wings per user). Realized moves are deliberately simple single-point reads through the pricing interpolant (only the 9M knot interpolates): sticky-strike ATM change at each knot, and (Δσ₁₁₀ − Δσ₉₀)/4. Sens grouping is per-leg shape *evaluation* (`key_rate_sens` on u·vega, and on u·vanna for the VaR cross term) — never a pillar-grid representation of the shapes (a 9M tent isn't representable on the TTM pillars, which have no 0.75 node) and free of the bucketed-vega side-lobes; `bumped_key_rate_sens` measures the same 8 numbers in 16 revaluations (matches closed form to 6e-4 at the literal 1-pt bump). `key_rate_pnl` mirrors `greeks_pnl` with the vol+vanna terms swapped; `rolling_var_keyrate` is a greeks-only rolling pass (4th pass in `run_var_rolling.py`, cache `data/var_rolling_keyrate.csv`, joins the cached full reval). **Verdict (`key_rate.ipynb`)**: interpretable and lean — the call-spread book is structurally a *skew* book (last date ≈ +$0.9M per unit tilt vs $160k/pt net level vega, concentrated 6–9M) — but at this simplicity it loses to fitted factors: attribution R² 0.705 vs PCA k=3's 0.811 (k=8 0.927), bulk error tails ≈ k=3 but max 2× worse ($1.4M on 2020-03-16, whose smile move is violently non-monotonic in moneyness — curvature outside the level+tilt span, so the 3-point reads scored a −$1.26M estimate against a +$140k truth); rolling hedged VaR99 mean |gap| 7.4% +cube / 8.3 plain vs 5.6/4.7% for PCA k=4c/k=10c, better on only ~⅓ of days, >10% gap on 29% of days, and the **same crisis tail** (2020-03-16 −67% vs −61%: the displaced-book failure is realized-move curvature, basis-independent — still owned by the gate/screen); raw VaR gap 3.3% vs 0.9% (k=10c). The single-date VaR read (−0.7%, beating greeks k≤5 as-of 2026-05-12) was a mirage — the third single-date reversal in this project. Measured headroom for round two: butterfly reads (90+110−2·ATM)/2 lift the in-sample ceiling 0.705→0.790, a wider 80–120 skew read alone reaches 0.750, a short-end read adds nothing — all just extra rows of the same sens/score machinery.

- `rainbow.py` — **multi-underlying exotic valuation** (user spec 2026-08-05), the template for the real book's simulation-priced rainbows: a 1Y call spread (strikes 100/112% — cap wider than the vanilla book's 110 because the structure prices cheaper) on the ranked basket `B = 0.5·best(P_spx, P_sx5e) + 0.3·worst + 0.2·P_hsi`, sold at $1M notional, evaluated only on joint-quote dates. Pipeline: per-index risk-neutral marginals by Breeden–Litzenberger (`implied_marginal`: undiscounted calls through the bicubic smile on a log-spaced performance grid, CDF = 1 + C′, quantile function for sampling; recovered mean matches the forward to <1bp, asserted in tests) → Gaussian copula (`sample_performances`) with one constant historical correlation matrix (`historical_corr` on **5-day overlapping** log returns — daily returns understate cross-region co-movement badly under asynchronous closes: SPX–HSI 0.17 daily vs 0.43 at 5d, flat by 10d) → USD (SPX-curve) discounting, no FX/quanto per spec. **Wing lesson**: the pricing grid's flat 50/150 clamp kinks σ(x) where the put wing still has vega — a ~2–3% Dirac of teleported probability mass, −30bp mean bias — while untapered slope continuation violates Lee's bound on rising call wings (HSI's rises); the fix is edge-slope continuation tapered exponentially (scale 50 mon pts, floored), leaving ~1e-4 residual negative-density mass. First valuation (`rainbow_option.ipynb`, 2026-07-31, 400k paths, se $79): **$53.1k per $1M (5.31%)** — ~14% under SPX-alone at the same strikes (basket diversification + surrendering SPX's rich +3.7% forward carry), ≈ the price of an SPX 100/110, which is the "cheaper structure funds the wider cap" design; rank premium (0.1·E|P_spx−P_sx5e| ≈ 1.1 perf pts) is worth only ~$2.9k inside the cap vs the plain 40/40/20 basket; and the price is **near correlation-neutral** (±0.2 on all pairs, or daily-vs-5d corr, moves it <0.6% — basket-vol and rank-premium channels cancel), so the constant-historical-ρ shortcut is benign for this payoff. `marginal_call_spread` prices single-index spreads by quadrature off a marginal (no paths); `price_rainbow` is the one-call wrapper a future daily-sold rainbow book will loop over. Validation & integration speed (2026-08-05 review): notebook section 5 re-implies each smile from vanillas priced on the simulated paths via `bs_implied_vol` — construction round-trips ≤0.2bp, simulated vanillas 3–13bp mean MC noise (worst ~46bp at the dying-vega 60% wing) — so the sampler demonstrably feeds the basket the markets' option-implied distributions; and `sample_performances(method="sobol")` (scrambled QMC, powers of two) cuts integration error to ~N^-0.85: **1,024 Sobol paths ≈ 400k pseudo-random** ($83 vs $79 RMSE against a 4M-point reference), the ~400× lever for future book×scenario VaR sweeps. `price_rainbow_quad` (user-requested 2026-08-05) goes all the way to deterministic: HSI integrated out analytically conditional on the two copula normals (the conditional payoff is a shifted call spread in P_hsi, priced as the integral of the conditional survival curve on the marginal's grid via precomputed normal-score tables Φ⁻¹(F(x))), then Gauss–Hermite (outer) × Gauss–Legendre in copula-uniform space (inner) with the inner integral **split at the rank kink** P_spx=P_sx5e so each panel is smooth — 8,192 nodes reproduce the 4M-path Sobol reference to $0.13 in ~0.6s with zero seed variance (2,048 nodes ~4bp; small-n convergence is algebraic, not spectral — the shared piecewise-linear quantile tables carry micro-kinks). It replaces MC outright for ≤3 European underlyings but doesn't generalize to the real book's path-dependents, so MC+QMC stays the reference engine. Both pricers take `perf_to_date` (per-index S_asof/S_sale; total performance = g·X, strikes in sale-date units) to season options; the seasoned evidence table (user-requested 2026-08-05, notebook): one 5,000-node rule across six vintages (sold 0–11M ago, τ 1.0→0.11, pv $53k→$109k as the basket runs into the cap) stays within $0.4–4.1 of the 4M-Sobol reference — ≤0.5bp of price everywhere — where pseudo-MC needs 10⁸–10¹⁰ paths and Sobol 33k–262k+; honest caveat: at matched single-price accuracy Sobol is a few× faster in wall-clock on CPU (paths cost less than nodes) — the quadrature's edge is zero variance (noise-free bumped greeks) and fixed batchable shape.

- `rainbow_torch.py` — **batched GPU engine for the quadrature** (user go-ahead 2026-08-05), built shaped for the attribution/VaR stages: `QuadBatch.from_problems` stacks B `QuadProblem`s (three marginals, corr, df, seasoning `perf_to_date`) into device tensors — one option is a batch of 1, the daily-sold book a batch of ~250, a VaR sweep a stream of batches — and `price_quad_batch` mirrors `price_rainbow_quad` line-for-line (returns a differentiable (B,) pv tensor; `price_rainbow_quad_torch` is the batch-of-one wrapper). Numerics: fp32 only for the survival matrix + trapezoid panels (the `(B, nodes, grid)` tensors that dominate — consumer fp64 runs at 1/64 rate), fp64 for node placement, table interps and the cumulative-integral accumulation (`survival_dtype=torch.float64` for full parity); chunked under `max_bytes` (default 2GiB); the batched `np.interp` equivalent (searchsorted right=True + clamped lerp) matches the numpy engine's deduplicated quantile interp everywhere quadrature weights are non-negligible. Parity (tests pin it): fp64 ~1e-11 vs numpy, fp32 < $0.001/option on $1M notional. Autograd: the survival stage is gradient-checkpointed per chunk (without it, backward pins every chunk's survival tensor and OOMs the 8GB card at book scale); one backward = exact d(pv)/dg for all vintages×indices (vs central bumps: 1.4e-5 rel), 8.5s for 750 deltas ≈ the cost of the six bumped revals it replaces but exact and parameter-count-free. ## Datasets: `SPX_volSurface.csv`, `SX5E_volSurface.csv`, `HSI_volSurface.csv`

Implied-vol surface snapshots for three indices, one file per underlying, identical schema (~33.7k rows each). Coverage 2018-12-27 through 2026-07-31: 1,969/1,970/1,971 dates after cleaning, **1,969 joint dates** where all three quote (rainbow work only evaluates on those), ~17 terms per date out to ~9.5Y, no month-long gaps (max calendar gap 4 days). Each row is one term (expiry) of one day's surface; a day's full surface spans multiple rows sharing the same `AsOfTime`. Quirks handled by the loader: 17 non-EOD rows (SPX), ~200–221 exact-duplicate (date, term) rows per file, 6 repaired far-call-wing rows (SPX). **These files replaced the original `SPX_volSurface 2.csv` (2013-12-30→2026-05-12, ~55k rows) on 2026-08-05** — committed notebook outputs and cached `data/` results for the vanilla-book/VaR studies were computed on that longer history and will shift if the pipeline is rerun on the new SPX file.

Columns:
- Unnamed first column: integer row index.
- `50, 60, 70, 80, 90, 95, 100, 105, 110, 120, 130, 140, 150`: implied vols (in %) at moneyness levels expressed as percent of spot (100 = ATM).
- `AsOfTime`: snapshot timestamp (e.g. `2013-12-30T23:59:59Z`), the natural time-series key.
- `Term`: option expiry date; combined with `AsOfTime` gives time-to-maturity.
- `Forward`, `ImpliedSpot`, `DiscountFactor`: per-term forward, spot, and discount factor.
- `DataSourceId`, `IsEndOfDay`, `UnderlyingIndex` (always SPX), `VolSurfaceId`, `VolSurfaceTypeId`: metadata.

The stray `* N.csv:Zone.Identifier` files are Windows download artifacts and can be ignored.
